# ADR-005：Quiet Reader 视觉方向

- 状态：**Accepted design direction**
- 日期：2026-09-11
- 范围：Reader 阅读壳、顶部工具栏、TOC/工具面板、选区操作、AI 输出卡片和应用 UI 设计系统

## 背景

Reader 当前已经具备 Library、TOC、翻译、摘要、理解、词典、聊天、笔记、标注和 TTS 等能力，但阅读页的默认视觉重心仍然偏向“工具面板”：

- 顶部同时放置返回、翻译、阅读视图、来源链接和工具控制；
- 右侧工具面板一次展示 12 个标签，3 列网格在窄宽度下竞争图标、文字和选中态；
- AI 输出虽然支持部分 Markdown，但不同面板的层级、操作按钮和内容容器不一致；
- 正文、应用 UI 和辅助功能的视觉边界需要继续保持清晰。

参考 [xiaolai/paper-one](https://github.com/xiaolai/paper-one) 的项目定位和取舍：它将自己定义为个人阅读应用，核心围绕 EPUB/PDF 阅读、标注、笔记和少量上下文解释，而不是一个持续展示所有能力的复杂产品界面。这里借鉴的是“阅读优先、低干扰、按需出现”的设计原则，不复制其品牌、代码、字体或具体布局。

## 决策

Reader 采用 **Quiet Reader** 作为后续阅读页的视觉方向：

1. **正文是第一视觉层级**：默认状态优先展示书籍内容，TOC 和工具能力不抢占阅读视线；沉浸式阅读模式仍保留，并作为明确的快捷入口。
2. **工具按需出现**：顶部只保留阅读流程必需操作；TOC 与 AI 工具使用紧凑的折叠入口或工具轨道，展开后才显示完整能力。
3. **选区优先**：Explain、Translate、Dict、Take Notes 等高频操作应贴近当前选区出现；不要求用户先在 12 个工具标签中寻找功能。
4. **AI 是阅读辅助层**：AI 结果使用统一的纸张式内容容器，先显示目标/上下文，再显示回答，复制、加入笔记等操作保持低权重但可发现。
5. **建立稳定的版式关系**：正文使用独立的阅读主题和排版尺度，应用壳使用语义设计 tokens；二者不共享会互相覆盖的颜色或字体规则。
6. **所有新增或修改的设计值 100% token 化**：颜色、字号、间距、圆角、边框、阴影、控制高度和字距均从 `src/styles/tokens.css` 或阅读主题定义消费。
7. **可访问性不因“安静”而削弱**：折叠工具必须有明确的可访问名称和状态，键盘、焦点、对比度、缩放和窄窗口布局继续作为验收条件。

## 不采用的方案

- 不直接复制 `paper-one` 的品牌资产、源代码、配色或具体页面结构。
- 不删除现有 AI、TTS、标注、搜索和 Library 能力；只是降低默认视觉噪音。
- 不在本 ADR 中改变 EPUB/PDF/Markdown 的内容模型、定位协议或数据库结构。
- 不用一套阅读主题覆盖应用壳，也不把书籍 CSS 直接当作应用 UI 样式。
- 不用颜色、阴影或动画替代清晰的信息层级。

## 影响

### 正面影响

- 首屏更像阅读器，长时间阅读时认知负担更低；
- 工具数量继续保留，但按任务和上下文组织，减少寻找成本；
- AI 输出在不同面板之间具有一致的扫描路径；
- 设计 token 和公共控件成为后续页面修改的可执行边界。

### 成本与风险

- 默认收起面板会改变已有用户的操作习惯，需要提供清晰的展开入口并保留状态反馈；
- 选区浮动操作需要处理窄窗口、滚动、焦点恢复和与 EPUB WebView 的边界；
- 视觉验收不能只依赖前端构建，必须在真实 Tauri 窗口中验证主题、缩放、面板宽度和键盘操作。

## 验收条件

- Reader 默认状态下正文是主要视觉焦点，TOC/工具面板不会与正文争夺同等层级；
- 工具入口在 1024px 最小窗口宽度、200% UI 缩放和深色应用主题下仍可发现、可操作；
- 选区操作可在不打开工具标签网格的情况下完成 Explain、Translate、Dict 和 Notes；
- AI Markdown 的标题、列表、引用、代码块、链接和操作区在 Chat、Understand、Deep Analysis 等面板中视觉一致；
- `npm run check:styles`、`npm run build`、`npm run test:ui` 通过，并完成真实 Tauri 窗口回归；
- 所有新/改动 UI 设计值通过语义 token 消费，不引入 raw color、默认字号或任意设计值。
