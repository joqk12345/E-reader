# Reader 0.5.3 PDF 移除盘点

日期：2026-09-11  
依据：[`ADR-006`](../adr/006-product-slimming-epub-markdown.md)

## 结论

PDF 目前不是一个孤立模块，而是贯穿导入、数据类型、Library 筛选、ReaderContent 渲染、Rust parser/command、错误模型和测试的横切 Feature。应先拆除入口和调用链，再删除实现；不能直接删除单个 parser 文件。

## 盘点清单

### 前端入口与状态

- `src/types/index.ts`：`Document.file_type` 与相关类型包含 `pdf`；历史兼容必须保留识别能力。
- `src/store/useStore.ts`：`currentDocumentType`、`importPdf`、`import_pdf` 调用。
- `src/features/library/useLibraryImport.ts`：文件选择器扩展名、`.pdf` 分支和 `importPdf` 注入。
- `src/features/library/useLibraryDocumentFilters.ts`：PDF 类型过滤器和计数。
- `src/components/Library.tsx`：导入文案、过滤器、空状态和历史文档入口。
- `src/components/DocumentCard.tsx`：PDF 标签显示和格式映射。
- `src/components/ReaderContent.tsx`：PDF 文本清理、表格/标题分类、页面图片 marker、原始 PDF iframe 和 PDF 专用分享上下文。
- `src/components/PdfParsedFlow.tsx`：PDF 专用组件，候选删除对象。
- `src/features/reader/useReaderRenderModel.ts`：需确认是否包含 PDF 分支；删除时仅移除 PDF 路径。

### Rust 实现

- `src-tauri/src/parsers/pdf.rs`：PDF parser 及其单元测试，候选删除对象。
- `src-tauri/src/parsers/mod.rs`：parser module 和 `PdfParser` re-export。
- `src-tauri/src/commands/import.rs`：`import_pdf` command。
- `src-tauri/src/commands/mod.rs`：command re-export/注册入口。
- `src-tauri/src/lib.rs`：Tauri invoke handler 中的 `import_pdf` 注册。
- `src-tauri/Cargo.toml`：直接依赖 `pdf = "0.8"`，候选删除；需以 lockfile/build 结果确认是否有间接依赖。
- `src-tauri/src/error.rs`：PDF 专用错误变体需在删除调用方后清理；通用错误编号不得被误改。
- `src-tauri/src/security.rs`：确认是否存在仅服务 PDF 的路径授权；EPUB/app-private 安全边界必须保留。

### 数据与兼容边界

- `documents.file_type` 以及旧 `sections`/`paragraphs` 数据继续保留，不能做破坏性 migration。
- 历史 `file_type = 'pdf'` 记录需要由 Library 安全展示 unsupported 状态，并允许删除。
- 历史 PDF 原始路径不能自动转换、覆盖或删除；删除 document 仅遵循既有删除语义。
- `src-tauri/src/database/v2_schema.rs` 中与 publication/旧 document 的兼容逻辑不能因 PDF Feature 删除而破坏。
- `src-tauri/src/commands/publication.rs` 目前包含 PDF 测试 fixture 数据；需保留数据库通用测试，删除 PDF 专用阅读/导入断言。

### 测试、fixture 和 smoke

- `src-tauri/src/parsers/pdf.rs` 内嵌 PDF parser 测试应删除。
- `src-tauri/src/commands/publication.rs` 中 PDF document 测试数据应改为历史 unsupported compatibility 测试或移除。
- `scripts/ui-smoke.mjs` 中 PDF mock document、PDF 相关 fixture 和扩展名应删除；EPUB/Markdown mock 必须保留。
- `scripts/check-design-boundaries.mjs`：删除 PDF 相关边界期望，但保留通用设计边界检查。
- `src` 中现有 Foliate、Locator、Publication 和 Markdown 测试不属于 PDF Feature，不应删除。
- 任何新增历史 PDF 兼容测试必须明确标记为 compatibility guard，而非 PDF Feature 测试。

### 文档与产品文案

- `README.md`、`FEATURES.md`（若存在）、`CHANGELOG.md`、`RELEASE.md`：更新支持格式和 0.5.3 说明。
- `docs/adr/001-004*.md`、`docs/plans/2026-08-19-reader-v2-refactor-plan.md`、Foliate spike 文档中涉及 PDF 的架构背景不能全局删除；只删除已不再成立的产品承诺，并保留历史决策上下文。
- `docs/adr/006-product-slimming-epub-markdown.md` 是新的范围决策，不是 PDF 实现删除清单的替代品。

## 删除后允许存在的 PDF 引用

仅允许以下类别：

1. 历史 `file_type` 识别和 unsupported UI；
2. 防止旧数据崩溃的兼容测试；
3. ADR、迁移、CHANGELOG 和 release notes 中的范围/迁移说明；
4. 数据库旧字段或不可破坏的通用历史数据描述。

禁止继续存在：PDF parser、PDF reader branch、PDF preview、`import_pdf` command、PDF adapter、PDF 导入入口、PDF 格式筛选、PDF 专用依赖和 PDF Feature fixture。

## 实施顺序

1. 先补入口/历史数据/EPUB-Markdown 保留能力的行为测试；
2. 删除前端导入入口和 Reader 分支；
3. 删除 Rust command/parser/依赖；
4. 清理测试、fixture、smoke mock 和文案；
5. 使用 `rg` 复盘允许/禁止引用清单；
6. 完成全量 gate 后再决定 0.5.3 发布。
