# Reader 0.5.4 CRAP 设计重构计划

- 状态：Historical baseline; Reader surfaces superseded by `2026-09-12-reader-robin-williams-refactor-plan.md`
- 日期：2026-09-12
- 依据：[`ADR-007`](../adr/007-crap-design-system-refactor.md)
- 前置版本：0.5.3 EPUB/Markdown 产品精简

## 目标

以 Contrast、Repetition、Alignment、Proximity（CRAP）为共同验收语言，统一应用壳、Library、Reader Chrome、工具面板和 AI 输出表面；保持正文优先，并让高频任务更容易发现。

## 非目标

不修改 EPUB 解析、安全、Locator、publication、数据库、Tauri IPC、阅读位置或现有搜索/翻译/AI/笔记/标注/TTS 行为；不重新加入 PDF。

## 工作包

### WI-01：设计审计与信息层级

范围：Library、Reader、TOC、ToolPanel、AI 面板。

验收：列出每个页面的主要/次要/辅助动作、内容层级、对齐边界和语义分组；标记违反 CRAP 的现有表面；不改代码。

状态：已完成，详见 [`CRAP 设计审计`](2026-09-12-reader-0.5.4-design-audit.md)。

### WI-02：Token 与共享表面
状态：已完成。

范围：`src/styles/tokens.css`、共享 Button/Input/Card/状态样式。

验收：颜色、字体、间距、圆角、边框、阴影、控件高度和字距全部使用命名 token；统一 hover、focus、disabled、loading、error；`check:styles` 通过。

### WI-03：Library 重构
状态：已完成。

范围：`Library.tsx`、`DocumentCard.tsx`、筛选与导入区域。

验收：标题、筛选、搜索、导入和批量操作形成清晰层级；卡片内容和操作对齐；EPUB/Markdown 入口突出，历史 PDF 保持可识别但不进入阅读流程；键盘和窄窗口无溢出。

### WI-04：Reader Chrome 与工具分组
状态：已完成。

范围：`Reader.tsx`、`TOCPanel.tsx`、`ToolPanel.tsx`。

验收：返回、标题、阅读设置和更多操作稳定对齐；工具按高频/低频任务分组；TOC 与工具展开关系清晰；正文区域不被工具挤压。

### WI-05：AI 面板与选区动作
状态：已完成。

范围：Chat、Summary、Understand、Deep Analysis、选区 Quick Actions。

验收：上下文、结果、状态和动作使用统一卡片结构；长内容可滚动换行；选区动作具备可访问名称、焦点恢复和边界定位；不改变 AI 调用合同。

### WI-06：主题、响应式与验收
状态：已完成。

范围：应用主题、阅读主题、UI smoke 和人工 Tauri 验收。

验收：应用 light/dark 与 White/Sepia/Night 阅读主题隔离；覆盖 1024px、1280px、1440px 和 200% 缩放；完成键盘、ARIA、对比度、错误态和 reduced-motion 检查。

## 实施顺序

1. WI-01 设计审计；
2. WI-02 建立共享 token 和组件规则；
3. WI-03 Library；
4. WI-04 Reader Chrome 与工具；
5. WI-05 AI 和选区动作；
6. WI-06 主题、响应式和真实窗口验收。

每个 WI 先写可观察测试，再做最小实现；每个工作包独立提交并可回滚。设计审计和文档可免行为 red，但最终仍必须通过 exact-tree TDD gate。

## 完成定义

- CRAP 四项原则在审计表中逐项有证据；
- 所有新增或修改的设计值来自 tokens；
- EPUB/Markdown 阅读及既有 AI、搜索、TOC、Locator、位置、笔记、标注和 TTS 回归通过；
- `npm run check:styles`、`npm run build`、`npm run test:ui`、相关单元/Rust 测试和 `npm run test:tdd:gate` 通过。
